## Findings

1. **Staging data growth after the restart is about 4.7 GB/day.**
   - The SMC database grew 32.4 MB in 10 minutes, and host free space fell at a matching rate.
   - This is far above the 0.7–0.9 GB/day estimated earlier. Part of it may be catch-up after
     5 hours stopped; one window cannot tell.
   - At this rate the 51.2 GB free lasts about 11 days.
   - The cause is the same per-quote evidence write found in P0 (`observe_equity`), now on the SMC
     side only.
   - Options: stop the staging API again with `p1b-stop-staging stop`, since the retirement is
     verified, or re-measure in a few hours.
2. **The staging API's CPU did not drop.**
   - The remaining CPU belongs to the SMC lab, so retiring PA freed disk I/O and memory but not CPU.
3. **Host memory headroom is down.**
   - Minimum available memory was 2.3 GiB, against 5.2 GiB in P0.
   - The cause is production, which now averages 7.12 GiB (peak 8.18 GiB) against 4.77 GiB in P0.
     Production was not changed today. The staging API stays capped at 1.5 GiB.
   - There is no swap. Worth watching.
4. **Cosmetic code issue.** The retired router is mounted twice (`/` and `/api/v1`), so FastAPI logs
   "Duplicate Operation ID" warnings when `/openapi.json` is generated. This is harmless.
